# Paired agent pilot — transmission and runner manifest

A separately authorized [reduced two-session pilot](hssm-workflow/iteration-3-handoff-pair/README.md)
was attempted after the user requested lower token use. Its baseline stopped at
the native token budget before producing a review; treatment did not start.
This original 12-session manifest remains a historical proposal, not launch authorization.

**Prepared only; not authorized to launch.** The executable settings and exact
prompt/input definitions are in
[agent-evaluation-round-1.json](agent-evaluation-round-1.json). No agent run,
model-service request, grading call, or result was created while preparing this
manifest. It covers the six-scenario paired pilot from
[validation-round-1.md](../plans/validation-round-1.md), with no trigger trials
or automatic follow-up runs.

## What the proposed pilot sends

Each of twelve fresh agent sessions would send its defined prompt and Codex's
materialized session instructions/tool declarations to the **OpenAI Codex
service**. As the agent reads files and runs local analysis, selected file
contents, command output, errors and generated figures may also enter subsequent
requests. Permission must therefore cover the input files and resulting analysis
conversation, not only the initial prompt.

The intended task payload is:

1. The scenario's `inputs`, copied byte-for-byte to the specified destination.
2. Its `materialized_json_inputs` and `environment.json`, serialized as defined
   in the manifest.
3. The listed `skill_payloads` for that arm: `SKILL.md`, required references and
   scripts. The baseline has `bayesian-workflow`; treatment adds only Bambi or
   HSSM as appropriate. There are 21 distinct skill-source files across the
   pilot; each arm receives only its specified subset.
4. The scenario Python/runtime libraries and the new code/results created in
   that run. Package-source inspection is allowed. Use installed packages,
   without editable dependencies on Spine or collaborator checkouts. The CLI
   host-read limitations below still apply.

The evaluator retains the manifest, source metadata, assertions, package-lock
provisioning files, arm labels and hashes outside the agent workspace. Do not
copy a repository directory wholesale. Exclude repository instructions,
notebooks, prior reports, saved fitted artifacts, grading rubrics, other arms'
outputs, unrelated global skills, private Spine context and user configuration.

The initial task text is exactly `shared_prompt_prefix`, two newlines, the
scenario `prompt`, two newlines, its concrete `pilot_settings_text`, and a final
newline. The manifest records the resulting UTF-8 `stdin_sha256`. This text is
provided on stdin using `codex exec -`; grading assertions are never appended.

## Model, tools and resource budget

- **CLI:** the inspected installation is `codex-cli 0.153.4`; its binary hash is
  recorded. The inspection used help/version/feature-list commands only; the options
  and observed model defaults were rechecked during the payload refresh. No
  model catalog request, prompt-input rendering or agent command ran.
- **Model:** explicitly `gpt-6-astra`, reasoning effort `ultra`, matching the
  selected nonsecret local configuration fields. These are identifiers, not an
  immutable model revision or a new access check. Record any reported model
  metadata during an authorized run; do not silently substitute a model.
- **Run count:** six scenarios, two arms each, serial execution, no automatic
  retries. Neutral run IDs and alternating arm order are fixed in `planned_order`;
  the arm mapping remains evaluator-only.
- **Wall time:** 30 minutes per modeling arm, 10 minutes per deferred/review arm;
  at most 4 hours total for twelve runs. A supervising controller must enforce
  these limits and terminate the process group, preserving partial evidence.
- **Modeling:** one fit per modeling arm; two chains, 1,000 tuning and 1,000
  retained draws per chain, one worker process. Bambi uses 500 prior draws;
  HSSM uses 200. Fit seeds are fixed in the manifest. Predictive work and
  deterministic checks are allowed; additional fits require new authorization.
- **Tools:** intended capabilities are local shell commands, local file
  reads/edits and viewing locally generated figures. Package installation,
  network requests, web/search, browsers, account connectors, other agents and
  cross-thread tools are outside the pilot. The actual tool inventory remains
  unverified and must be described as a limitation until inspected.
- **Token/cost bound:** no verified per-run token or money limit appears in the
  inspected CLI help. Wall-clock and run-count limits are not cost guarantees.
  Record actual usage if emitted. This manifest does not authorize unlimited
  retries or automated model-based grading.

The `candidate_argv` is the proposed command, not a tested isolation recipe. It
sets the model and effort explicitly, uses workspace-write plus approval policy
`never`, omits the base user config, preserves execpolicy rules, requests an
ephemeral session and JSON event output, and disables known optional feature
flags. It never uses the approval/sandbox bypass flags. Do not execute it without
separate transmission authorization. Review the remaining preflight checks and
disclose unresolved limits with that request.

## Isolation gaps that remain

`--ignore-user-config` omits the base `$CODEX_HOME/config.toml`; it does not
promise to suppress every global skill, managed configuration, project
instruction or tool provider. `--ephemeral` concerns session persistence.
Workspace-write does not prove restricted host **reads**. Preserve existing
execution-policy rules. No approval or sandbox bypass is proposed.

Use a fresh temporary workspace outside Spine, copy only the selected payload,
and use explicit model/settings overrides. The manifest disables observed
optional feature flags, but their effect on the final catalog/tool list has
not been verified. Record any extra context or capabilities and the resulting
risk of contamination between arms. The proposed pilot does not require a new
OS account or container, and does not claim this setup creates hard isolation.

Local help exposes `codex debug prompt-input`, but does not establish that it is
offline or equivalent to `exec --ignore-user-config`; it was not run. Prefer a
local inspection if local help or source establishes that it sends no model
request. Otherwise disclose the unverified catalog/tool inventory in the
transmission request. No model-service call is permitted merely to investigate
this during preparation. Never copy authentication material into task payloads.
